## Cloudflare machine-only ingress (prepared; transport switch is separate)

`POST /api/machine/execution/` is an alias for the existing signed machine gateway. It exists so the Cloudflare Access application can protect `/admin/*` and the interactive browser APIs, including `/api/execution*`, while the fixed machine URL stays outside interactive login. It does not require an additional Cloudflare service credential. The existing `CMS_EXECUTION_SECRET`, timestamp window and exact signed body remain mandatory; no secret or transport URL is changed by adding this route.

The alias reads the actual request stream with a maximum of500000 bytes and cancels an oversized stream before decoding, signature verification or JSON parsing. It then verifies the original gateway HMAC, parses a JSON object and rejects the presence of **any top-level `operation` property**, regardless of value. This includes a correctly signed rollback packet sent alongside a valid browser session. Header removal alone cannot enforce that boundary because `headers()` retains the visitor's original Next request context.

Only a packet that passes that boundary is reconstructed byte-for-byte and delegated to the unchanged original `POST /api/execution` implementation. That implementation re-verifies HMAC and retains its scope, schema, approved recipe, request lease, CAS, immutable history, receipts and draft-only rules. The alias has no GET, rollback, publication or user-management handler and accepts no query parameters. An HMAC authorizes machine synchronization only.

The original `GET /api/execution?effectKey=...`, browser rollback POST and `/admin/execution` remain unchanged and require the verified browser/CMS administrator boundary. Do not create an Access bypass for those routes. On the native Sites origin, its existing provider service-access requirement remains in place; this alias does not bypass native hosting ingress.

Focused verification: `node --experimental-strip-types scripts/test-machine-execution.mjs` tests exact signed bytes, unchanged-handler delegation, signature-before-parse ordering, the streamed byte limit/cancellation, POST/query boundaries, and rejection of every operation value despite a correct HMAC and an admin-session context. `node scripts/test-machine-execution-http.mjs` sends denial cases only to loopback: GET405; unsigned/malformed/spoofed requests401 or unconfigured503; oversize413; and a signed fixture rollback denied. It refuses non-loopback targets and never sends an accepted packet.

The worker/broker URL remains unchanged until the first actual Cloudflare deployment is accepted. Root then coordinates the counterpart's fixed-origin machine URL change, live signed microbatch/receipt checks and existing connector rollback. A prepared endpoint or local denial test does not prove that the server has switched or synchronized successfully.
